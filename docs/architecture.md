# 架构与出口边界

## 流量路径

```mermaid
flowchart LR
    W[Windows 客机] -->|隔离 LAN| L[OpenWrt LAN]
    L -->|TCP 重定向 / DNS 接管| M[Mihomo]
    M -->|只允许配置的 SOCKS5 入口| N[VMware NAT]
    N --> T[宿主 TUN 与上游中转]
    T --> S[固定出口代理]
    S --> I[目标 HTTPS 服务]
```

宿主 TUN 接管来自网关 NAT 的连接；上游中转负责到达 SOCKS5 入口，SOCKS5 代理负责最终目标连接。宿主实际规则与连接链必须核对，不能用全局代理组的选择推断规则模式的转发结果。

## 示例地址规划

| 角色 | 示例 |
|---|---|
| 客机网段 | `10.42.0.0/24` |
| 网关 LAN | `10.42.0.1` / `br-lan` |
| 管理网段 | `192.168.56.0/24` |
| 宿主管理地址 | `192.168.56.1` |
| 网关管理地址 | `192.168.56.10` / `eth1` |
| 出口示例 | `192.0.2.10:1080`，文档保留地址，不能实际连接 |

这些值已经替换，不对应原机器。接口名称、宿主管理来源及 DHCP 设置必须与实际虚拟网络一致。

## 失败关闭机制

`guardian_gateway` 是独立受管表，output、input 与 forward 采用默认丢弃。允许项包括回环、精确管理 SSH、DHCP、客机必要返回流量与唯一的 IPv4/TCP 代理入口。客机 TCP 重定向至本机代理端口，DNS 重定向至网关解析器。

网关解析器须把查询送至代理 DNS 端口，Mihomo 的上游 DNS 应通过指定出口访问。模板自身不会替你配置 dnsmasq、网卡或 DHCP。IPv6 防护同时依赖系统设置、服务启动顺序和热插拔处理。

代理进程退出时，独立防护表继续存在；核心重启不会自行解除防护。SOCKS5 UDP 未启用，客机非 DNS UDP 无直连放行。此选择会影响会议、游戏等依赖 UDP 的功能。

## 防护刷新修复

原先 `flush table` 能清空链中的规则，却未消除已有命名集合中的旧入口元素。本项目使用同一个 `nft -f` 事务执行：

```nft
table inet guardian_gateway {}
delete table inet guardian_gateway
table inet guardian_gateway {
    # 重新定义集合、计数器和规则
}
```

先 `nft -c -f` 校验，再事务性应用。重建会重置表内计数器，不应把重置后的零值解释为历史从未有流量。表仅供本项目管理，不应与其他程序共享写入。

## 信任边界

- 管理 SSH 必须独立可达，密钥和 known_hosts 由操作者提供。
- 代理凭据只用于获准的入口配置与认证，不写入报告或命令行参数。
- 中转与出口供应商仍属于外部依赖；本项目不对其可用性或信誉作认证。
- TLS 使用正常证书校验，不通过关闭验证来使测试通过。
- 网关 HTTPS 成功不能替代客机、浏览器和应用层验收。
